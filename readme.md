# reportmd 仕様書

* バージョン：0.1.0（初期仕様案）
* ステータス：設計中
* 言語：Ruby
* 文書形式：Markdownベースの独自拡張形式
* ファイル拡張子：`.rmd`

## 1. 概要

### 1.1 目的

`reportmd` は、Markdownの簡潔な記法を維持しながら、大学のレポートなどに必要な組版機能を追加する文書作成ツールである。

HTMLやCSSを直接記述せずに、本文を執筆し、用紙サイズ・余白・フォントなどを設定ファイルで管理し、PDFとして出力できることを目指す。

### 1.2 設計方針

1. 本文は可能な限り標準的なMarkdownで記述する。
2. 独自構文は、短く直感的な記号を使用する。
3. 通常のMarkdown文書の解釈を可能な限り維持する。
4. 文書全体の設定と本文の記述を分離する。
5. 独自構文の処理を独立したモジュールとして実装する。
6. 将来的な機能追加やVS Code拡張の開発を考慮する。

## 2. 対象環境・使用技術

| 項目            | 技術          |
| ------------- | ----------- |
| 実装言語          | Ruby        |
| 入力形式          | `.rmd`      |
| 設定形式          | JSON        |

## 4. コマンドライン仕様

### 4.1 基本コマンド

```bash
reportmd build report.rmd
```

指定した入力ファイルからPDFを生成する。出力先を省略した場合、入力ファイルと同じディレクトリに同名のPDFを出力する。

### 4.2 出力先の指定

```bash
reportmd build report.rmd -o output.pdf
```

### 4.3 設定ファイルの指定

```bash
reportmd build report.rmd -c setting.json
```

### 4.4 オプション

| オプション            | 説明        |
| ---------------- | --------- |
| `-o`, `--output` | 出力PDFのパス  |
| `-c`, `--config` | 設定ファイルのパス |
| `-h`, `--help`   | ヘルプ表示     |

## 5. 標準Markdownの対応範囲

本文はMarkdownを基本とし、以下の機能を利用できることを目指す。

* 見出し
* 段落
* 太字・斜体
* 箇条書き・番号付きリスト
* 引用
* リンク
* 表
* 画像
* フェンス付きコードブロック
* 数式
* 脚注

具体的な対応範囲は、PandocのMarkdown拡張設定と実装時の検証によって確定する。

コードブロックにはバッククォート3個またはチルダ3個以上のフェンスを使用できることを目指す。

## 6. 独自構文

### 6.1 基本方針

独自構文には、意味を連想しやすい記号を使用する。本文に `reportmd` などの専用キーワードを毎回記述する方式は採用しない。

### 6.2 改ページ

記法案：

```markdown
前のページの本文

^

次のページの本文
```

単独行の `^` を改ページ指示として扱う。

通常の文章中に含まれる `^` は改ページとして扱わない。コードブロック内の `^` も変換しない。

### 6.3 右揃え

記法案：

```markdown
--> 2026年10月12日
--> 大阪工業大学
```

行頭の `-->` を右揃え指示として扱う。

連続する右揃え行をひとつのブロックとして処理する案を採用する。空行によるブロック終了などの詳細は実装前に確定する。

### 6.4 中央揃え

記法案：

```markdown
<-> 実験レポート
```

行頭の `<->` を中央揃え指示として扱う。

左揃えは標準状態とし、専用の記号を設けない。

### 6.5 インデント

記法案：

```markdown
通常の段落。

  この段落は1段階インデントする。
```

行頭の半角スペース2個を1段階のインデントとして扱うことを目指す。

ただし、Markdownでは行頭のインデントがコードブロックやリストのネストなどに使われるため、以下を必須の設計条件とする。

* フェンス付きコードブロック内の空白を変更しない。
* リスト・引用・その他のMarkdown構文を不必要に変換しない。
* 4スペース以上のインデントについては、標準Markdownとの互換性を確認したうえで扱いを決める。
* インデント量と変換対象の判定方法は、テストを通して確定する。

### 6.6 図表番号
#### 図

記法案：

```markdown
![f：システム構成図](images/system.png)
```
* f：figure（図）
* ： 以降：タイトル・キャプションの文字列
* 画像の代替テキストにも同じ文字列を使う
* 段落を分ける空行とは区別する。

#### 表
```mardown
![t：実験結果]
| 条件 | 結果 |
|---|---|
| A | 10 |
| B | 20 |
```
* t：table（表）
* ： 以降：タイトル・キャプションの文字列
* 次の Markdown 表と関連付ける

キャプションは、空行の有無にかかわらず「直後の対象要素1つ」にだけ関連付ける、といった単純なルールから始める。

## 7. 設定ファイル

### 7.1 形式

設定ファイルはJSONとし、初期ファイル名を `setting.json` とする。

### 7.2 設定例

```json
{
  "document": {
    "paper": "a4",
    "title": "実験レポート",
    "author": ""
  },
  "page": {
    "margin": {
      "top": "25mm",
      "bottom": "25mm",
      "left": "25mm",
      "right": "25mm"
    },
    "numbering": true
  },
  "text": {
    "font_size": "10.5pt",
    "line_spacing": 1.5,
    "paragraph_indent": 0
  },
  "font": {
    "main": "IPAexMincho",
    "mono": "Noto Sans Mono CJK JP"
  },
  "caption": {
    "figure_position": "bottom",
    "table_position": "top"
  }
}
```

### 7.3 設定項目

| 項目                      | 意味          |
| ----------------------- | ----------- |
| `document.paper`        | 用紙サイズ       |
| `document.title`        | 文書タイトル      |
| `document.author`       | 著者名         |
| `page.margin`           | 上下左右の余白     |
| `page.numbering`        | ページ番号の有効・無効 |
| `text.font_size`        | 本文の文字サイズ    |
| `text.line_spacing`     | 行間          |
| `text.paragraph_indent` | 段落の既定インデント  |
| `font.main`             | 本文フォント      |
| `font.mono`             | 等幅フォント      |

各項目は、実装時に適用処理と検証処理を用意する。未実装の設定を読み込んでも、反映済みであるかのように扱ってはならない。

## 8. PDF生成仕様

1. `.rmd` ファイルをUTF-8として読み込む。
2. 独自構文の前処理を行う。
3. MarkdownをPandocで解析する。
4. 必要な書式変換を適用する。
5. XeLaTeXでPDFを生成する。
6. 成功時には出力先を表示し、失敗時には原因を確認できるエラーを表示する。

PDF生成時に一時ファイルを使用する場合は、正常終了・異常終了のいずれでも不要な一時ファイルが残らないようにする。

## 9. エラー処理

少なくとも以下を検出する。

* 入力ファイルが存在しない
* 設定ファイルが存在しない、またはJSONとして不正
* 設定値が許容範囲外
* 独自構文の記述が不正
* PandocまたはXeLaTeXが利用できない
* PDF生成に失敗した

エラーは標準エラー出力に表示し、失敗した場合は正常終了を示す終了コードを返さない。

## 10. テスト方針

独自構文の実装では、正常系だけでなく標準Markdownへの影響もテストする。

* 通常のMarkdownからPDFを生成できる。
* 日本語が正常に表示される。
* 表・画像・数式・脚注が利用できる。
* 改ページ・右揃え・中央揃えが適用される。
* インデントが規則どおり適用される。
* コードフェンス内の記号が変換されない。
* 通常の文章中の記号が誤変換されない。
* リスト・引用・見出しなどの意味が保たれる。
* 不正な設定や構文に対してエラーを返す。
